# ShopXO v6.8 后台能力对齐清单（GoShop）

> 提及 **ShopXO** 仅用于功能对照说明，不代表官方关系或背书。

对照 **ShopXO 商家后台** 常见模块，对当前 **GoShop 管理端**（`admin/`，菜单见 `AdminShell.tsx`）做可核对分级。状态含义：

| 状态 | 说明 |
|------|------|
| **已对齐** | 有对应页面与后端能力，可满足常规运营（细节可能与 PHP 版有差异）。 |
| **部分对齐** | 有能力缺口、仅占位、仅 API 无后台页、或菜单未挂载等，需人工留意。 |
| **占位** | 界面或文档明示未完成，不应假设与 ShopXO 一致。 |
| **不适用** | Go 栈/产品形态下无 1:1 对应（非「偷懒未做」）。 |

> 统计口径与路由数以 `HANDOVER.md`、`scripts/doc-metrics.sh` 为准。本表侧重 **后台菜单与页面**；**uni-app** 以 `shopxo_compat.go` 的 82 个 `s=` 动作为准。

## 3. 客户端与架构（非后台菜单）

| 范围 | 状态 | 说明 |
|------|------|------|
| ShopXO uni-app | **已对齐** | `api.php` 单入口 + **82** 个 `s=` 动作（含 `cashier/paydata` 小程序收银台）；边界 case 以集成测试与真机为准。 |
| ShopXO PC 模板商城 | **不适用** | GoShop PC 为 `web/`（Next.js），功能对齐度需单独对照，不等同 PHP 模板页。 |
| PHP 插件包 / Composer / 在线升级 | **不适用（产品外）** | 不内置 PHP 运行时与官方升级通道；与「应用商店」同为**刻意不对齐**项，见 `HANDOVER.md` 产品边界。 |
| PayPal 等 | **部分对齐** | 驱动与沙盒存在程度见 `payment_driver`；实盘与商户资质见 `HANDOVER` P3。 |

## 4. 维护方式

1. 改后台菜单：编辑 `admin/src/components/AdminShell.tsx` 的 `menuItems`。  
2. 改规模数字：运行 `./scripts/doc-metrics.sh`，同步 `HANDOVER.md`。  
3. 本表更新：新增页面或占位变更时，调整对应行状态与说明。

---

## 5. 小结（如何理解「约 97%」）

- **商家日常后台主路径**（商品、订单、用户、网站、手机、支付日志、RBAC、仓库等）：多为 **已对齐**。  
- **与 ShopXO 的结构性差异**：**插件市场、PHP 在线升级、任意 PHP 插件**已明确为 **产品边界外**（非「待开发短板」）；见 `HANDOVER.md`。  
- 若将「完美复刻」定义为必须包含上述能力，则属于 **刻意不对齐**，而非实现进度问题。
